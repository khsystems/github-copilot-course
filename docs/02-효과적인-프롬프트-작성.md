# STEP 02: 효과적인 프롬프트 작성

## 학습 목표

Copilot이 이해하기 쉬운 요청을 작성하는 방법을 배웁니다.

## 프롬프트란?

프롬프트(Prompt)는 **Copilot에게 보내는 질문이나 작업 요청**입니다.

사람에게 일을 부탁할 때 자세히 말할수록 결과가 좋아지는 것처럼, Copilot에게도 무엇을 만들지 분명하게 알려 주는 것이 좋습니다.

> [!TIP]
> 프롬프트 = Copilot에게 보내는 작업 설명서

## 프롬프트에 포함할 내용

다음 네 가지를 알려 주세요.

1. **목적**: 무엇을 만들고 싶나요?
2. **사용자**: 누가 사용하나요?
3. **조건**: 꼭 지키거나 빼야 할 것은 무엇인가요?
4. **완료 모습**: 무엇이 되면 완성인가요?

짧고 모호한 요청:

```text
할 일 앱 만들어 줘.
```

조금 더 좋은 요청:

```text
회의 준비가 익숙하지 않은 사람을 위한 체크리스트 웹페이지를 만들고 싶습니다.
준비 항목을 추가하고, 완료 표시하고, 전체 삭제할 수 있어야 합니다.
교육에서 제공한 연습 프로젝트 안에서 만들어 주세요.
현재 프로젝트의 기존 설정은 유지하고 새로운 프로그램은 추가하지 마세요.
로그인 기능은 만들지 마세요.
아직 파일을 만들지 말고 먼저 작업 순서를 알려 주세요.
```

## 짧은 요청을 구체적인 요청으로 바꾸기

### 1단계: 만들고 싶은 것 적기

`나는 _____을 만들고 싶습니다.`를 완성합니다.

### 2단계: 사용할 사람 적기

`이것은 _____을 위한 것입니다.`를 완성합니다.

### 3단계: 꼭 필요한 기능 하나 적기

`사용자는 _____할 수 있어야 합니다.`를 완성합니다.

### 4단계: 하지 않을 것 적기

로그인, 결제, 알림처럼 오늘 만들지 않을 기능을 적습니다.

### 5단계: 계획 먼저 요청하기

바로 파일을 만들게 하지 말고 어떤 순서로 만들지 먼저 물어봅니다.

## 실습 프롬프트

```text
아래 아이디어를 Copilot이 이해하기 쉬운 요청으로 정리해 주세요.

만들고 싶은 것: [여기에 작성]
사용할 사람: [여기에 작성]
꼭 필요한 기능: [여기에 작성]
오늘 만들지 않을 기능: [여기에 작성]

빠진 내용이 있다면 질문을 세 개까지만 해 주세요.
아직 파일은 만들거나 수정하지 마세요.
```

## 문제 해결 가이드

- 결과가 너무 복잡하면 `오늘 2시간 안에 만들 수 있게 줄여 주세요`라고 말합니다.
- 모르는 기술이나 설치를 제안하면 `현재 프로젝트의 기존 설정을 유지하고 새로운 프로그램은 추가하지 마세요`라고 말합니다.
- 한 번에 기능을 많이 요청하지 말고 가장 중요한 기능부터 요청합니다.
- 원하는 결과와 다르면 처음 목적과 사용자를 다시 알려 줍니다.

## 학습 완료 확인

- [ ] 무엇을 만들지 적었습니다.
- [ ] 누가 사용할지 적었습니다.
- [ ] 꼭 필요한 기능 하나를 정했습니다.
- [ ] 오늘 만들지 않을 기능을 정했습니다.
- [ ] 파일을 만들기 전에 계획을 먼저 요청했습니다.
